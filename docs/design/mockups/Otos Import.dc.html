What's wrong, in CRAP terms
Proximity: the count "42 new" sits two rows away from the button that acts on it, while the destination and the two checkboxes — both pre-flight decisions — are separated by an unrelated status row. Alignment: three rows, three different left edges and three different type sizes, so the eye has no column to follow. Contrast: "Ready" and "Import" carry equal visual weight; the most important fact on the bar (how many, how big) is set in the smallest, faintest type. Repetition: status appears here and again as a sidebar spinner. And the copy explains the planner rather than the outcome.

One owner per fact
While the bar is on screen for a source, the bar owns progress and the sidebar row shows nothing. The sidebar indicator only appears when you've navigated away — that's what makes it an indicator rather than a duplicate. When import starts and the view jumps to the new import batch, the same bar travels with it, so there is still exactly one progress surface.
Motion
The bar slides up 24px with a fade when a card mounts (0.35s, spring). State changes cross-fade the left block and swap the right button in place — the bar never changes height, so the grid doesn't reflow mid-import. The done checkmark scales from 0.6 with a soft overshoot, then the bar holds for six seconds and slides away. All of it collapses to a cross-fade under Reduce Motion.
Lighter grays
Sidebar and bar move from the default window gray to near-white (#FAFAFB / #FBFBFC), and the separators drop to 7–9% black hairlines instead of the standard 13%. Dark mode keeps Apple's elevation order: #1C1C1E content, #2A2A2C bar. Accent stays the system accent color, so a user who runs purple gets purple.
